# Pilot visual quality review

**Decision: correct specific foreground/layout failures before using these features for thesis pairwise similarity.** The files are numerically well formed, but the visual evidence does not yet support treating foreground coverage and grid occupancy as comparable UI-content descriptors across all five applications. Exploratory comparisons could diagnose sensitivity; they should not be interpreted as validated consistency measurements.

## Scope and evidence

Reviewed 12 screens from all five applications, including the lowest two and highest two values for foreground coverage, edge density, and retained component count (overlapping selections), plus forms, chart, announcement, booking, and dark-theme document screens. This is a purposive stress sample, not an estimate of dataset-wide error frequency.

See [complete contact sheet](contact_sheet.png), readable pages [1](contact_sheet_1.png), [2](contact_sheet_2.png), [3](contact_sheet_3.png), and [selection with exact metrics and source plots](selected_screens.csv). Columns show the original dataset image, existing foreground mask, existing edge map, existing bounding boxes, and existing layout overlay. Diagnostic panels were copied from saved PNGs; features were not recomputed. The original column is displayed from the source image at higher source detail; feature panels reflect the pipeline's resized image. Compare structures rather than fine pixel sharpness. Layout colors represent bounding-box union occupancy, not foreground probability.

Only new files under `visual_quality_review/` were created. Dataset, metadata, algorithms, and existing `results/` files were left unchanged; this report deliberately does not overwrite `results/validation_report.md`.

## Numerical validation versus visual quality

**Numerical:** read-only checks in this review passed for all 82 existing successful records: aligned screen IDs across outputs; 1–5 color clusters; proportions summing to one; finite Lab coordinates; density values in [0,1]; valid normalized boxes; and 32 layout entries in [0,1]. The earlier implementation report records five passing tests and matching smoke/full-run outputs. Determinism and extraction tests were not rerun here. These checks establish structural validity, not correct segmentation or perceptual usefulness. Color-palette perceptual quality is outside this focused five-panel review.

**Visual:** all 12 selected rows were inspected in the contact sheets. Failures concern what pixels/components represent, despite valid numerical ranges. No manual masks or box annotations exist for quantitative accuracy assessment.

Severity: **High** = blocks interpreting the affected descriptor across screen types; **Medium** = meaningful bias or loss requiring correction or explicit methodological acceptance; **Low** = mostly plausible result with a localized limitation. Severity is a visual judgment, not a calibrated score. F denotes foreground pixel fraction; E denotes Canny edge fraction; C denotes retained component count.

## Required next steps and acceptance gate

1. **Correct background handling first.** Gradient and mixed-background screens need a documented strategy; lowering one global threshold alone does not address both. Reinspect masks and layout on these two failure cases and the full 12-screen sample after any approved change.
2. **Define the analyzed region.** Source attribution footers are acquisition artifacts. Decide consistently how to treat device status/navigation areas and synthetic rounded screen frames. Genuine in-app navigation must remain. Apply any later policy to derived images only, preserving raw data and metadata.
3. **Resolve the layout construct.** Connected components are not UI elements: text fragments, touching cards merge, and chart envelopes cover empty space. Choose whether this is acceptable for the thesis's box-based descriptor. If accepted, rename/describe the interpretation precisely; if UI-element structure is intended, validate a corrective grouping/boundary approach before similarity. Do not change the agreed box-union method silently.
4. **Address pale outlines with evidence.** Compare a small manually marked sample of inputs, tables, and dark cards. Check recall of important boundaries and false detections on shadows/backgrounds; avoid selecting thresholds solely to improve these examples.
5. **Rerun numerical checks and visual review after corrections.** Require no near-full-screen layout caused solely by a background gradient, consistent exclusion of acquisition artifacts, and explicit acceptance of remaining misses/merges on the annotated sample. Quantitative accuracy targets should be set with thesis supervision; this review does not invent calibrated thresholds.

The edge maps broadly reflect visible text and controls, with expected low-contrast misses. Their numerical correctness does not establish that edge density alone measures consistency. No similarity metrics, calibration, extraction changes, or new feature results were produced in this review.
