# Final baseline-preserving gradient correction

This directory contains **one fixed optional correction**, evaluated once on the original 12 review screenshots. It does not modify or replace `extract_features.py`. The correction function defaults to disabled. See [the final decision](run_01/validation_report.md): a narrow sample PASS recommending only a reviewed, controlled full-pilot rerun, with no automatic promotion.

## Reproduce

Use the existing environment from the project root:

```sh
LOKY_MAX_CPU_COUNT=1 .venv/bin/python experiments/final_baseline_correction/correct.py --output experiments/final_baseline_correction/reproduction_01
LOKY_MAX_CPU_COUNT=1 .venv/bin/python -m unittest -v test_features
LOKY_MAX_CPU_COUNT=1 .venv/bin/python experiments/final_baseline_correction/test_correction.py -v
```

The experiment refuses an existing output directory and paths outside this directory. The test reads the archived `run_01`. No packages were installed. NumPy, OpenCV, Pillow, and the unchanged baseline/library helpers are reused; installed versions are in the root `requirements-lock.txt`.

`correct_mask(rgb, baseline, enabled=False)` returns an unchanged copy by default. The experiment explicitly passes `enabled=True` to test the single candidate. Parameters were fixed before inspection of its outputs and were not swept or changed afterward. No polynomial models, local background replacements, morphology, new color rules, or new feature definitions are introduced.

## Controlled ROI and preserved files

Both conditions use the **same complete processed original screenshot**, exactly as production does: EXIF orientation, RGB conversion/white alpha composition, aspect-preserving thumbnail fitting within 512×512, no upscaling. No cropping or new ROI classifier is applied. This deliberately preserves original footer/frame/chrome contributions; it makes the baseline numerically identical to the saved baseline, rather than comparing a cropped candidate against an uncropped original.

All PILOT files, metadata, baseline results/source/tests, original review files, v2 experiments and row-tuning files are protected by before/after SHA-256 checks (generated bytecode caches excluded). They are not overwritten. New outputs, test logs and documentation exist only here.

## Failure mechanism: an important correction to the earlier interpretation

The baseline bins perimeter RGB values by integer division by 16, picks the most frequent bin, and estimates one median RGB background from pixels in that bin. Every pixel farther than 25 RGB units from that vector becomes foreground.

On `APP02-FLOW01-S01`, the selected RGB vector is [47,47,47], belonging to the acquisition footer. The footer's nearly uniform perimeter values win over the many colors of the actual gradient. The threshold then marks almost the entire gradient as foreground. Even without the footer, one background color cannot represent the spatially varying gradient: prior ROI-only results still had foreground coverage about .511 versus .961 on the complete image. Thus both perimeter contamination/ROI sensitivity and the single-color classification rule contribute. The final experiment keeps the complete ROI and corrects the mask directly, separating that effect from cropping.

On `APP05-FLOW01-S04`, the selected vector is [215,227,223], the **light panel**, not a dark header. The original mask leaves the empty light panel black and marks dark headers, cards and bottom region white. Earlier report language suggesting that the baseline selects a dark background and marks the whole light panel foreground was incorrect; those historical files are preserved. The .610 coverage is not itself evidence of failure. Remaining issues include merging neighboring cards, counters/text matching the light background becoming holes in dark foreground regions, frame contributions, and representing all backgrounds with one color. There is no justified reason to apply a smooth-gradient suppression rule to these abrupt, mostly flat regions. The correction abstains and preserves this screen exactly.

## Single correction: gated removal of a smooth boundary-connected region

The intent is to remove only the broad, slowly varying background falsely selected by the baseline, while leaving filled controls isolated by their sharp boundaries. This is a postprocessing subtraction from the existing mask, not a replacement estimator or a semantic UI segmentation model.

Activation requires all of:

1. Each side margin has a sustained smoothly varying color run: at least one quarter of image height, RGB range magnitude at least 40, and consecutive median RGB changes no larger than 6.
2. Baseline foreground coverage is greater than .5. This is supporting evidence, never the sole test.
3. A connected low-step region occupies at least .35 of image area and reaches both side borders.

Only the largest qualifying smooth region is suppressed. No other pixels are added, no enclosed interiors are filled or removed explicitly, and no new noise filter is applied. Sharp boundaries can isolate the constant-color interiors of buttons/cards from the background, preserving their fill. Low-contrast boundaries can fail to isolate a region; a genuine broad gradient UI element may be mistaken for background. These are known limitations, not solved by the diagnostic gate.

### Mathematics and every symbol

Let I(p) be the processed three-channel RGB vector at pixel p=(x,y), with x=0,…,W−1, y=0,…,H−1. W,H are image width/height in pixels, and N=WH is image area. RGB values are in [0,255]. ||·||₂ is Euclidean vector norm, Σ means summation, |·| means set size, ∩ means intersection, and 1[condition] is one if true and zero otherwise.

The original background estimate is b0. For perimeter pixel RGB vector z, quantization is floor(z/16) channelwise, with floor rounding down. The most frequent quantized vector selects the bin; ties choose lexicographically first. b0 is the channelwise median of original RGB vectors in that bin. The original mask is M0(p)=1[||I(p)−b0||₂>25]. Its coverage is F0=Σ_p M0(p)/N.

Let b=max(1,round(.035W)) be side-band width, where round is nearest integer. Define L(y)=median_{x<b} I(x,y) and R(y)=median_{x≥W−b} I(x,y), channelwise. For either profile P=L or P=R, split its rows into maximal consecutive runs T where ||P(y+1)−P(y)||₂≤6. For a run T, its length fraction is |T|/H; its color span is s(T)=||max_{y∈T}P(y)−min_{y∈T}P(y)||₂, using channelwise max/min. Each profile qualifies if some run has |T|/H≥.25 and s(T)≥40. The two sides need not qualify on identical row intervals; this is a heuristic limitation.

For any pixel p, let A(p) be its existing four side-sharing image neighbors. Define d(p)=max_{q∈A(p)}||I(p)−I(q)||₂, where q is a neighboring pixel. Let S={p:d(p)≤6}, the low-step pixel set. Find four-connected components Q of S (paths of pixels sharing a side). Qualifying components have |Q|/N≥.35 and intersect both x=0 and x=W−1 borders. Select Q* with greatest pixel count; ties use the smallest deterministic component label.

Let g be true only if both profiles qualify, F0>.5, and a qualifying Q* exists. With the correction explicitly enabled, define

    M1(p) = M0(p) · 1[p is not in Q*]   if g is true,
    M1(p) = M0(p)                      otherwise.

M1 is the corrected foreground mask and · is scalar multiplication. Disabled execution always returns M0. Thus M1(p)≤M0(p): the correction cannot create foreground pixels or expand any existing bounding-box union. It can nevertheless delete genuine foreground if the gate or smooth-connectivity assumption is wrong. Corrected coverage is F1=Σ_p M1(p)/N, and ΔF=F1−F0 is its signed change. These quantities are not accuracy scores.

### Unchanged numerical feature definitions

K-Means works on unique RGB vectors u_j with multiplicities n_j, j=1,…,U, where U is the number of unique vectors. Set K=min(5,U). It minimizes J=Σ_j n_j||u_j−μ_(a_j)||₂², where J is clustering cost, μ_k is cluster k's RGB centroid, a_j is vector j's cluster assignment, k=1,…,K. K-Means++/Lloyd uses seed 42, ten initializations, one computation thread. Proportion q_k=Σ_{j:a_j=k}n_j/N, summing to one. Float RGB centroids convert through sRGB linearization and D65 XYZ to standard CIELAB via OpenCV. In conventional color notation L*=116f(Y/Yn)−16, a*=500[f(X/Xn)−f(Y/Yn)], b*=200[f(Y/Yn)−f(Z/Zn)]. X,Y,Z are tristimulus values; Xn,Yn,Zn are reference-white values; L* is lightness and a*,b* are signed chromatic coordinates. f(t)=t^(1/3) for t>δ³ and t/(3δ²)+4/29 otherwise, where δ=6/29 and t is a normalized tristimulus value. The star is part of each conventional Lab name. Palettes are computed by the original function, unchanged for both conditions.

Canny density D=Σ_p E(p)/N, where E(p) is one for a detected edge and zero otherwise. The original grayscale, 5×5 Gaussian blur with standard deviation σ=1 pixel, Canny thresholds 50/150, 3×3 Sobel aperture, L1 gradient, and hysteresis are untouched. Gaussian kernel weights are proportional to exp(−(i²+j²)/(2σ²)), normalized to sum to one; i,j are integer offsets −2,…,2 and exp is the exponential function. L1 gradient is the sum of absolute horizontal and vertical derivatives. Both conditions reuse the exact same E and D; foreground coverage and edge density stay separate.

For either foreground mask, retain eight-connected components with area at least 12 pixels. This final feature connectivity is unchanged; the correction's separate smooth-region connectivity is four. For each retained foreground component, x0,y0 are inclusive minimum pixel coordinates and x1,y1 exclusive maximum coordinates. Normalized box = [x0/W,y0/H,x1/W,y1/H]. Let V be the union of pixels inside all retained rectangles, so overlaps count once and empty rectangle interiors still count. Components are not semantic UI elements.

Grid boundaries are c_i=floor(iW/4), i=0,…,4, and h_j=floor(jH/8), j=0,…,8. Cell G_(j,i) contains c_i≤x<c_(i+1) and h_j≤y<h_(j+1). Occupancy v_(4j+i)=|V∩G_(j,i)|/|G_(j,i)| for column i=0,…,3 and row j=0,…,7. Vector v has 32 row-major entries in [0,1]; they need not sum to one. Mean occupancy is Σ_l v_l/32, with l=0,…,31. Reported cell change is Δv_l=v_corrected,l−v_original,l. Component-count change similarly means corrected minus original. Color and edge differences are exactly zero.

For example, 200 foreground pixels among 1,000 image pixels give F=.2. Suppressing 50 of those pixels gives F=.15 and ΔF=−.05; that alone says nothing about whether they were correctly removed.

## Outputs, evidence and stopping rule

`run_01` includes the full configuration, trigger decisions/run spans, estimated baseline background RGB vectors, before/after numerical files, all 32 cell differences, saved ROI/mask PNGs, 12 side-by-side comparison figures and three contact sheets. Existing sparse patch annotations from row tuning are reused for descriptive pixel counts (`patch_counts.csv`); no new ground truth or accuracy percentages are invented. Patch coordinates are evaluation-only, not correction rules. Test logs are beside this README. Hash manifests establish input/history preservation and source provenance.

On this sample, the gate activates once and abstains eleven times. A synthetic horizontal-only gradient documents a missed case: neither side varies vertically, so the gate abstains despite a real gradient. Abrupt mixed backgrounds also intentionally remain unresolved. There is no basis for estimating trigger sensitivity/specificity on unseen screenshots. Further segmentation optimization stops here. A sample PASS permits only recommendation of a reviewed controlled full-pilot rerun, not automatic promotion or a claim that all foreground extraction is accurate.
