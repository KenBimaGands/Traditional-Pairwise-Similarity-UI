# Traditional pairwise visual comparison

This module compares saved descriptors independently of navigation. It does not infer consistency, assign feature weights, or construct graphs.

## Selected feature version and inputs

The approved feature set is `results_corrected_pilot/`, following the explicit selection of the final optional correction and its authorized application to all 82 pilot screenshots. It retains baseline color/Canny features and changes foreground/layout only for APP02-FLOW01-S01. It is not the earlier experimental A/B/A1/A2 extraction. No screenshot pixels, boxes or segmentation are regenerated by this pairwise pipeline.

`pairwise_baseline.py` reads `visual_features.csv`, `layout_vectors.csv`, and `color_palettes.json` from that directory. `configuration.json` and `run_summary.json` are fingerprinted for provenance. `screens.csv` and `flows.csv` identify membership. Every screen must have exactly one successful scalar record, one valid palette and one 32-cell layout; ID sets must match exactly. Every flow must map to its stated application. Duplicate IDs/columns, unsuccessful extraction, nonfinite values, invalid proportions or out-of-range bounded features stop processing. No partial missing-feature pairs are silently exported.

Application/flow IDs only select and label pairs. No transitions, roles, screenshot names, navigation distances or graph relationships affect a score. Metadata order also does not define cluster correspondence.

## Code and reproduce

- `pairwise_baseline.py`: validate saved inputs, enumerate pairs, calculate distances/similarities, export summaries and provenance.
- `test_pairwise_baseline.py`: numerical/reference examples, pair membership/counts, invalid inputs, symmetry/identity, and repeated full exports.
- `plot_pairwise_distances.py`: render the already exported raw distances, without recomputing features or scores.

Run from the project root with the existing environment:

```sh
.venv/bin/python -m unittest -v test_pairwise_baseline
.venv/bin/python pairwise_baseline.py --smoke --output results_pairwise_smoke_reproduction
.venv/bin/python pairwise_baseline.py --output results_pairwise_baseline_reproduction

```

Use fresh output paths: scoring refuses to overwrite an existing directory. The plotter reads `results_pairwise_baseline` and writes only its visualization subdirectory. No packages were installed. Saved configuration records NumPy 2.2.6, SciPy 1.18.1 and scikit-image 0.26.0, source SHA-256 and input SHA-256 fingerprints. For another feature version, call `run(output, features_dir, metadata_dir)` explicitly and document the methodological change. Do not mix baseline and corrected features across methods.

## Notation and pair selection

Let A and B denote two screenshots, not applications. Let g(s) be screenshot s's application ID and f(s) its flow ID. A pair is an unordered set {A,B} with A≠B and g(A)=g(B). Stored IDs are lexicographically ordered only to make export order deterministic. A pair is `within_flow` if f(A)=f(B), otherwise `cross_flow`.

For application a with n_a screens, pair count is N_a=n_a(n_a−1)/2. Let F_a be its set of flows and n_(a,t) the number of its screens in flow t. Within-flow count is W_a=Σ_{t∈F_a} n_(a,t)(n_(a,t)−1)/2, and cross-flow count is X_a=N_a−W_a. Σ denotes summation, ∈ membership, ≠ inequality and braces denote an unordered set. No self-pair or reversed duplicate is generated.

## Raw features versus distances

Raw features describe one image: Lab centroids and proportions, foreground fraction F_s, edge fraction E_s, and layout vector v_s. A distance describes two images; zero indicates identical descriptors under that comparison. A similarity is a separately defined transformation where larger values mean closer descriptors. A future weighted composite would be a new aggregation, not an existing column here. Consistency classification would require a separate justified interpretation/calibration; similarity and consistency are not synonyms.

## Color: CIEDE2000 ground costs

A palette is a weighted discrete distribution P_A=Σ_(i=1)^m p_i δ_(c_i), and similarly P_B=Σ_(j=1)^n q_j δ_(d_j). Here m,n are cluster counts, each between 1 and 5; c_i and d_j are three-coordinate CIELAB centroids; p_i and q_j are nonnegative pixel proportions with Σ_i p_i=Σ_j q_j=1; δ_c means unit mass at color c. Lab lightness L* is nominally 0–100, while a*,b* are signed chromatic coordinates. The star is conventional color-coordinate notation, not multiplication.

The cost to move color mass between centroids is C_ij=ΔE_00(c_i,d_j), calculated by the established [scikit-image CIEDE2000 implementation](https://scikit-image.org/docs/stable/api/skimage.color.html#skimage.color.deltaE_ciede2000), using k_L=k_C=k_H=1. The formula combines corrected differences:

    ΔE_00 = sqrt[(ΔL′/(k_L S_L))² + (ΔC′/(k_C S_C))²
                 + (ΔH′/(k_H S_H))²
                 + R_T (ΔC′/(k_C S_C))(ΔH′/(k_H S_H))].

Δ denotes a difference; primes indicate CIEDE2000-adjusted quantities. ΔL′ is lightness difference, ΔC′ corrected chroma difference, and ΔH′ the hue-related difference expressed in chromatic-distance units. S_L,S_C,S_H are the standard lightness/chroma/hue sensitivity functions; R_T is the standard chroma–hue interaction term. k_L,k_C,k_H are viewing-condition factors, all fixed to one here. `sqrt` is the nonnegative square root and superscript ² means square. Corrected chroma/hue, neutral-color branches and hue wrap-around follow the library, rather than a new abbreviated implementation. Their complete standard subformula definitions and worked tests are in [Sharma, Wu and Dalal's implementation notes](https://hajim.rochester.edu/ece/sites/gsharma/ciede2000/ciede2000noteCRNA.pdf), equations 2–22. These named sensitivity functions are standard library calculations, not adjustable feature weights.

The reference test checks Lab [50,2.6772,−79.7751] against [50,0,−82.7485], expecting approximately 2.0425. We do not divide color differences by 100 or assert a universal maximum. CIEDE2000 is a perceptual color-difference formula; no triangle-inequality guarantee is required or claimed for the resulting screenshot descriptor distance.

## Color: balanced Earth Mover's Distance

For transport matrix T with entries T_ij representing mass moved from centroid i to centroid j:

    D_color(A,B) = min_T Σ_(i=1)^m Σ_(j=1)^n T_ij C_ij
    subject to T_ij ≥ 0,
               Σ_j T_ij = p_i for every i,
               Σ_i T_ij = q_j for every j.

D_color is the raw optimal transport cost, `min` means choose the feasible matrix with minimum objective, and ≥ denotes greater than or equal. All source mass is transported to all destination mass, with both totals equal to one. Cluster index is not a correspondence: mass can split across several target clusters, and colors may be reordered without changing the optimum.

The linear program uses [SciPy `linprog`](https://docs.scipy.org/doc/scipy/reference/optimize.linprog-highs-ds.html), HiGHS dual simplex (`highs-ds`), nonnegative bounds and equality marginals. One redundant marginal equation is omitted in the solve and checked afterward. No entropic regularization, cluster-index matching, or extra division by cluster count is used. Proportions must sum to one within absolute tolerance 10⁻¹⁰; accepted distributions are divided by their own sum only to remove floating-point summation drift. Primal/dual feasibility tolerances are 10⁻⁹; full marginal residual must be at most 10⁻⁸. These tolerances concern numerical feasibility, not UI consistency.

Mass totals of one make the transport objective an average ground cost per unit pixel mass; no additional solver normalization or cost scaling is applied. Multiple optimal transport plans can exist, but only their scalar minimum cost is used. Canonical Lab/proportion ordering improves deterministic behavior. Exact CSV reproduction was checked in the installed environment; arbitrary cross-version/platform byte identity is not promised.

Example: black Lab [0,0,0] and white [100,0,0] have ground difference 100 under the chosen settings. Palette (.75 black,.25 white) versus (.25 black,.75 white) must move .5 mass between black and white, yielding cost .5×100=50. Reordered identical palettes yield zero; splitting the same color into duplicate support entries with the same total mass also yields zero.

## Density: two independent absolute differences

    D_foreground(A,B) = |F_A−F_B|
    D_edge(A,B)       = |E_A−E_B|.

F_A,F_B are the saved foreground pixel fractions; E_A,E_B are the saved Canny edge fractions. |x| is scalar absolute value. Both distances lie in [0,1]. For foreground .20 versus .35, D_foreground=.15. For edges .02 versus .05, D_edge=.03. These are separate descriptors with no density average or weights.

Foreground estimates inherit the extraction heuristic, correction trigger, acquisition artifacts and missed pale details. Edge density depends on the fixed resolution, contrast and Canny preprocessing. Similar fractions can arise from very different image content.

## Layout: corresponding-cell mean absolute difference

    D_layout(A,B) = (1/32) Σ_(l=0)^31 |v_(A,l)−v_(B,l)|.

l indexes the existing 32 grid cells in row-major order: four columns left-to-right, then eight rows top-to-bottom. v_(A,l),v_(B,l) are saved rectangle-union occupancy values in [0,1]. D_layout lies in [0,1]. A cell difference of .8 with all other cells identical gives .8/32=.025. All-zero versus all-one vectors yield distance 1.

No boxes or connected components are recomputed. This compares occupied spatial envelopes at corresponding grid positions, not semantic component matching; empty rectangle interiors, text fragmentation and merged controls affect it.

## Distance-to-similarity conversion

For each bounded descriptor k in {foreground, edge, layout}, S_k(A,B)=1−D_k(A,B). S_k is its separate similarity, in [0,1]. Identical descriptors give 1. The example distances .15 and .03 give similarities .85 and .97. There is no final composite column.

**Color similarity is intentionally absent.** A defensible proposal for later approval is S_color(A,B;τ)=exp(−D_color(A,B)/τ), where exp is the exponential function, τ>0 is a fixed, externally justified color-distance scale in the same units as D_color, and the semicolon marks a parameter rather than another image. This maps zero distance to one and decreases monotonically; at D_color=τ it equals exp(−1), approximately .368. τ must be chosen through a justified external criterion/calibration before a final thesis mapping is adopted. No τ is chosen, no provisional color similarity is exported, and pilot min/max values are never used to normalize scores.

## Summaries, output interpretation and limitations

`pairwise_summary.csv` groups by application and `within_flow`, `cross_flow`, or `all`. These groups do not alter any score. For group values x_1,…,x_r, r is pair count, mean μ=Σ_t x_t/r and sample standard deviation s=sqrt[Σ_t(x_t−μ)²/(r−1)], where t indexes pairs. Standard deviation is blank when r=1, because it is undefined. Minimum/maximum are group extremes; median and quartiles use NumPy's linear-interpolation quantiles: for sorted zero-based values z_0,…,z_(r−1), probability p, h=(r−1)p, j=floor(h), α=h−j, Q(p)=(1−α)z_j+αz_min(j+1,r−1). floor rounds downward; min selects the smaller index. Q(.25),Q(.5),Q(.75) give the reported quartiles/median. All populated numeric values must be finite.

Plots show **distances**, not similarities or consistency. Matrices mirror unordered distances and display zero on self diagonals solely for visualization; self-pairs are absent from CSVs. The raw color colorbar is shared across applications and uses observed maximum solely as a display limit; no normalized color scores are created. Other colorbars use distance bounds 0–1. Four separate panels prevent misleading direct comparison of color units with bounded descriptors.

Pair counts grow quadratically. Shared screens make pair observations dependent; no inference test or claim that a group is more/less consistent is made. A low color distance can coexist with a high layout distance. Spatially permuted screens may share the same palette/density, and similar occupancy does not imply identical controls. The smoke selection is diagnostic and deliberately nonrandom.

For a fair future graph comparison, reuse the same saved features, pair IDs, raw descriptor distances and separately justified transformations. Graph/context features, composite weights and classification would require separate methods; they are not present here. No transition file is read by this implementation.
