# Phase 1 audit: existing architecture and gaps

Scope is the complete traditional visual-only workflow before graph construction. No graph implementation or output is included. Original source, dataset, metadata, prior results, existing repositories and installed skills were inspected without modification during the audit.

## Repository evidence

The local `Feature Extraction` repository points to `KenBimaGands/Feature-Extraction-Color-Density-Layout`; its remote README confirms a baseline package plus approved 82-screen snapshot and 12-screen evidence. The local `Traditional Pairwise Similarity` repository points to `KenBimaGands/Traditional-Pairwise-Similarity-UI`; remote inspection resolved its README under `tau-sensitivity-review/`, confirming that the published package is a numerical tau review, not the upstream scoring pipeline. Both remote inspections were read-only. No push, commit or installation was performed.

Existing skill definitions were inspected: the extraction skill guides the original workspace, while the tau package skill requires saved composite tables. Neither supplies the six-stage workflow alone. Similar folder names do not indicate a common executable pipeline.

Reviewed schemas/configuration cover 82 screen IDs, 709 within-application pairs (411 within-flow, 298 cross-flow), six source entry points, correction thresholds, edge epsilon/seed, fixed group weights and tau settings. The direct source is authoritative. The role/transition metadata is retained incidentally with the dataset, not used for scoring.

## Gaps addressed

Legacy scripts use project-root-relative imports and canonical output folders. Saved pairwise provenance contains machine-specific absolute input paths. Some figures use a macOS-only font. Diagnostics generate CSV/figures but do not automatically write fresh interpretive prose. Existing extraction/correction tests rely on the pilot, not arbitrary datasets.

The new package preserves a compatible runtime tree and supplies an orchestrator that clones it into a fresh workspace. Only location-bearing pairwise provenance is rebased there, after checking original digests. Recomputed upstream outputs replace private copies for downstream consumption, never source snapshots. A portable Matplotlib font replaces Menlo in two copied rendering functions; mathematics, source extraction behavior and research parameters are unchanged. `provenance.json` records original and packaged hashes and the precise rendering-only changes.

Historical reports remain available. For recomputed diagnostic/composite stages they are copied with `interpretation_provenance.txt`, explicitly identifying frozen interpretation rather than new human review. Tau's Markdown is generated by its actual script. No experiment is promoted based on new automatic judgments.

## Remaining boundaries

The ecosystem packages the complete fixed pilot, including images, frozen baseline/sample fixtures and saved diagnostics. It is not a generic new-dataset extractor, does not infer missing baseline fixtures, and does not create expert annotations. Individual stage routing still requires a complete compatible runtime project: the wrapper checks/copies the whole declared fixture manifest. Minimal table-only tau use remains available in the older standalone subpackage; that lightweight mode is not falsely described as full upstream execution.

Full installed-skill execution requires locating this repository; skills are instructions, not embedded Python/data distributions. User skill installation and GitHub publication are separate steps. Cross-platform fresh dependency installation and expert perceptual validation remain untested. No claim is made that full computation validates consistency or segmentation accuracy.
